### 原始请求（摘要）

开发一个 MCP Server，让 MCP 客户端或 Agent 可以创建和控制本地终端会话：启动命令、持续读取输出、向交互式进程写入、了解运行状态、需要时终止会话。它应是 Agent 可稳定使用的终端能力，而不是把单次 shell 命令包装成一个 Tool。验证场景：接入任意 MCP 客户端（例如 Manus），由客户端通过它创建并控制终端会话。先做最小可运行版本，再优化。

用户列出的设计关注点：MCP 接口设计；终端会话模型（会话 ID、PTY、cwd、env、stdout/stderr、退出状态、交互输入）；长任务与增量输出（非阻塞、分页/游标、内存、超时与取消）；并发与生命周期（隔离、客户端断开、进程退出、僵尸进程、服务重启后的清理与恢复）；安全边界（命令范围、工作目录、敏感环境变量、危险命令、用户审批、审计记录）。

### 决定

#### DEC-001: 技术栈

- **状态**： confirmed
- **决定**： Python 3.12 + uv + 官方 `mcp` Python SDK；PTY 使用标准库 `pty`/`os` 或 `ptyprocess`，不引入原生编译依赖；测试用 pytest + 真实 MCP stdio client。
- **备选**： TypeScript + `@modelcontextprotocol/sdk` + `node-pty`（需本机 node-gyp 编译，Node 25 兼容性待验证）。
- **原因**： 用户工具偏好 uv；asyncio 适合多会话非阻塞 IO；无原生依赖，安装和接入客户端更稳定。

#### DEC-002: 传输

- **状态**： confirmed
- **决定**： MVP 只提供 stdio 传输（Manus、Claude Code、Codex 均可直接以命令方式接入）。Streamable HTTP 与常驻 daemon 进入优化阶段。

#### DEC-003: Tool 集合（MVP 5 个）

- **状态**： confirmed
- **决定**：

| Tool | 作用 | 关键参数 | 关键返回 |
|---|---|---|---|
| `terminal_start` | 创建会话并启动命令 | `command`（缺省为用户登录 shell）、`cwd`、`env`、`mode`（`pty`/`pipe`）、`cols`/`rows`、`timeout_s`、`name`、`wait_ms`、`until` | `session_id`、`pid`、`status`、首段输出、`next_cursor` |
| `terminal_read` | 从游标增量读取输出 | `session_id`、`cursor`、`max_bytes`、`wait_ms`、`until`、`strip_ansi` | `output`（pipe 模式另含 `stdout`/`stderr`）、`next_cursor`、`dropped_bytes`、`has_more`、`status`、`exit_code` |
| `terminal_write` | 写入文本或控制键 | `session_id`、`text`、`keys`（如 `Enter`、`C-c`、`Up`、`Tab`）、`wait_ms`、`until` | 写入字节数、写入后的输出片段、`next_cursor`、`status` |
| `terminal_list` | 列出会话或查询单个会话状态 | `session_id`（可选）、`include_exited` | 会话摘要：命令、cwd、模式、状态、退出码/信号、开始/结束时间、输出总字节、最后活动时间 |
| `terminal_kill` | 终止会话 | `session_id`、`signal`（`TERM`/`INT`/`HUP`/`KILL`）、`grace_ms`、`remove` | 最终状态、退出码/信号 |

- **返回约定**： 所有 Tool 返回结构化结果（`structuredContent` + 文本摘要）；错误返回稳定的 `error.code`（如 `SESSION_NOT_FOUND`、`SESSION_EXITED`、`POLICY_DENIED`、`LIMIT_REACHED`、`INVALID_ARGUMENT`）和可操作的 `hint`。

#### DEC-004: 输出模型

- **状态**： confirmed
- **决定**： `pty` 模式（默认）合并 stdout/stderr，进程看到真实 TTY；`pipe` 模式无 TTY，分别返回 stdout 与 stderr。游标为会话内输出的绝对字节偏移；每会话环形缓冲默认 1 MiB，读取位置已被覆盖时返回 `dropped_bytes`；默认去除 ANSI 控制序列（可选原样返回）；UTF-8 增量解码，不在多字节字符中间截断。

#### DEC-005: 等待与不阻塞

- **状态**： confirmed
- **决定**： 默认立即返回；`wait_ms` 长轮询上限 30 秒，在有新输出、`until` 正则匹配或进程退出时提前返回；客户端取消请求只取消本次等待，不影响进程。会话可设 `timeout_s` 硬超时（TERM 后宽限再 KILL）。

#### DEC-006: 生命周期与恢复

- **状态**： confirmed
- **决定**： 会话归属于当前 MCP 连接；每个会话独立进程组。连接断开或服务正常退出时终止全部会话进程组（HUP/TERM → 宽限 → KILL）并回收子进程。会话元数据写入本地注册表；服务重启后按记录清扫仍存活的遗留进程组（校验进程启动时间防 PID 复用），旧记录标为 `lost` 可查询。已退出会话保留 10 分钟供读取后回收。断线重连保留会话进入优化阶段（需 daemon）。

#### DEC-007: 安全默认

- **状态**： confirmed
- **决定**： 配置文件定义：`allowed_roots`（cwd 必须位于其中，按 realpath 判断防符号链接逃逸；默认为服务启动目录）；继承环境变量时剥离敏感变量（名称匹配 `*TOKEN*`、`*SECRET*`、`*PASSWORD*`、`*_KEY`、`AWS_*` 等，可配置）；危险命令规则（如 `rm -rf /`、`mkfs`、`dd of=/dev/*`、`shutdown`/`reboot`、fork bomb、`curl … | sh`）在 `terminal_start` 和 `terminal_write` 的整行输入上检查，命中即拒绝；最大并发会话数默认 16；所有 Tool 调用与策略判定写入 JSONL 审计日志（输出正文不入审计）。

#### DEC-008: 用户审批

- **状态**： confirmed
- **决定**： MVP 对危险命令直接拒绝并给出原因；"询问用户后放行"通过 MCP elicitation 在优化阶段实现（客户端不支持时退回拒绝）。

#### DEC-009: 验证方式

- **状态**： confirmed
- **决定**： 自动化测试通过真实 MCP stdio client 驱动服务，覆盖下方全部 P1/P2 验收场景；另将服务注册到 Manus（本机 MCP / 自定义 MCP 连接器）跑通交互式会话场景，作为端到端验收。

### 用户场景与测试 *(必填)*

#### 用户故事 1 - 运行命令并取得结果与退出状态（优先级：P1）

Agent 启动一个会结束的命令（如构建、测试），等待其结束，拿到完整输出和退出码。

**独立测试**： 启动 `sh -c 'echo hi; exit 3'`，带 `wait_ms` 读取，即可验证。

**验收场景**：

1. **给定** 服务已连接，**当** 调用 `terminal_start` 运行 `echo hello` 且 `wait_ms=2000`，**则** 返回 `session_id`，输出含 `hello`，`status=exited`，`exit_code=0`。（NEED-001, NEED-004）
2. **给定** 命令以退出码 3 结束，**当** 调用 `terminal_list` 查询该会话，**则** `status=exited`、`exit_code=3`。（NEED-004）
3. **给定** 命令不存在，**当** 启动它，**则** 返回结构化错误或 `exit_code=127`，并带可读原因。（NEED-006）

#### 用户故事 2 - 长任务增量读取（优先级：P1）

Agent 启动长任务，随后多次读取新输出，期间可以同时操作其他会话。

**独立测试**： 启动每 200ms 打印一行、共 20 行的循环，用游标连续读取。

**验收场景**：

1. **给定** 长任务正在运行，**当** 以上次 `next_cursor` 调用 `terminal_read`，**则** 只返回新增输出，不重复、不遗漏，`status=running`。（NEED-002）
2. **给定** 一个 `terminal_read` 正以 `wait_ms=10000` 等待，**当** 同时对另一会话调用 `terminal_write`，**则** 后者立即完成，不被等待阻塞。（NEED-002）
3. **给定** 输出超过缓冲上限，**当** 从旧游标读取，**则** 返回 `dropped_bytes>0` 及仍保留的最新输出，服务内存不随输出无限增长。（NEED-002）
4. **给定** 会话设置 `timeout_s=2` 且命令持续运行，**当** 超时到达，**则** 进程被终止，状态显示为超时终止。（NEED-005）

#### 用户故事 3 - 控制交互式进程（优先级：P1）

Agent 启动交互式程序（Python REPL、shell、需要确认输入的 CLI），写入输入并读取响应，必要时发送 Ctrl-C。

**独立测试**： 启动 `python3 -i`，写入 `1+1` 回车并等待 `>>> ` 提示符。

**验收场景**：

1. **给定** `python3 -i` 已启动，**当** `terminal_write` 写入 `print(6*7)` 加 `Enter` 且 `until=">>> "`，**则** 返回输出包含 `42`。（NEED-003）
2. **给定** shell 会话中运行 `sleep 100`，**当** 发送 `keys=["C-c"]`，**则** 前台命令被中断，shell 会话仍为 `running` 并回到提示符。（NEED-003）
3. **给定** 程序检测 TTY，**当** 以 `pty` 模式启动，**则** 程序判定自己在终端中运行（如 `test -t 1` 为真）。（NEED-001）

#### 用户故事 4 - 终止与清理（优先级：P1）

Agent 终止不再需要的会话；客户端断开时服务清理全部会话，不留孤儿或僵尸进程。

**独立测试**： 启动会派生后台子进程的命令后 kill，检查进程表。

**验收场景**：

1. **给定** 会话运行 `sh -c 'sleep 300 & sleep 300'`，**当** 调用 `terminal_kill`，**则** 两个 `sleep` 进程都结束，返回最终状态与信号。（NEED-005）
2. **给定** 进程忽略 SIGTERM，**当** 以 `grace_ms=500` 终止，**则** 宽限后升级为 SIGKILL 并结束。（NEED-005）
3. **给定** 有多个运行中会话，**当** MCP 客户端断开（stdin EOF），**则** 服务退出且所有会话进程被回收，无孤儿进程。（NEED-005）
4. **给定** 会话已退出，**当** 对其 `terminal_write`，**则** 返回 `SESSION_EXITED` 错误，但仍可读取剩余输出。（NEED-004, NEED-006）

#### 用户故事 5 - 多会话隔离（优先级：P2）

**验收场景**：

1. **给定** 两个会话使用不同 cwd 和 env，**当** 分别执行 `pwd` 与 `echo $X`，**则** 各自输出互不串扰。
2. **给定** 已达最大会话数，**当** 再启动会话，**则** 返回 `LIMIT_REACHED`，已有会话不受影响。

#### 用户故事 6 - 安全边界与审计（优先级：P2）

**验收场景**：

1. **给定** `allowed_roots` 不包含 `/etc`，**当** 以 `cwd=/etc` 启动，**则** 返回 `POLICY_DENIED`，未启动进程。（DEC-007）
2. **给定** 服务环境含 `GITHUB_TOKEN`，**当** 会话执行 `env`，**则** 输出不含该变量。（DEC-007）
3. **给定** 危险命令规则，**当** 启动或写入 `rm -rf /`，**则** 返回 `POLICY_DENIED` 及命中规则说明，且审计日志记录该判定。（DEC-007）
4. **给定** 完成任意调用，**当** 查看审计日志，**则** 可找到时间、Tool、会话、命令、cwd、策略判定和退出结果。

#### 用户故事 7 - 服务重启后清理与可查询（优先级：P2）

**验收场景**：

1. **给定** 服务被强制杀死时仍有 `pipe` 模式会话进程存活，**当** 服务重新启动，**则** 遗留进程组被终止，`terminal_list(include_exited)` 中旧会话显示为 `lost`。（DEC-006）

#### 用户故事 8 - 接入 Manus 实测（优先级：P1）

**验收场景**：

1. **给定** 服务按文档注册到 Manus，**当** 在 Manus 任务中让 Agent 启动 `python3 -i`、计算表达式、读取结果并终止会话，**则** 全流程成功，Agent 无需额外说明即可正确组合 Tool。（NEED-006, NEED-007）

#### 边界情况

- `cwd` 不存在或不是目录：拒绝启动并说明。
- 输出含非法 UTF-8 或多字节字符跨块：以替换字符解码，不丢后续输出。
- 无换行的提示符（如 `Password:`、`>>> `）：`until` 仍能匹配。
- 短时间海量输出（如 `yes | head -c 50000000`）：服务保持响应，内存受限。
- 进程在等待期间退出：等待提前返回最终状态。
- 游标超过当前末尾或为负：返回 `INVALID_ARGUMENT`。
- 同一会话并发读取：各自按游标返回，互不影响；并发写入按到达顺序串行。
- 父进程退出但后台子进程仍持有 PTY：会话终止时整组回收。

### 需求 *(必填)*

#### 功能需求

- **REQ-F01**：系统必须提供会话化的启动、读取、写入、查询、终止能力。来源：NEED-001 ~ NEED-005
- **REQ-F02**：读取必须基于游标增量返回，默认不阻塞，可有上限地等待。来源：NEED-002
- **REQ-F03**：写入必须支持文本与命名控制键。来源：NEED-003
- **REQ-F04**：状态必须区分运行中、正常退出、被信号终止、超时终止、启动失败、重启后丢失。来源：NEED-004
- **REQ-F05**：终止必须回收整个进程组，客户端断开时清理全部会话。来源：NEED-005
- **REQ-F06**：所有返回必须结构化且错误码稳定、附带可操作提示。来源：NEED-006
- **REQ-F07**：必须可通过 stdio 接入标准 MCP 客户端，并提供接入文档。来源：NEED-007
- **REQ-F08**：必须提供 cwd 范围、敏感环境变量过滤、危险命令拒绝和审计日志。来源：用户关注点（默认值见 DEC-007）

#### 关键实体

- **Session（会话）**：ID、名称、命令、cwd、模式、终端尺寸、进程 ID/进程组、状态、退出码/信号、时间戳、输出缓冲与游标范围。
- **OutputBuffer（输出缓冲）**：有上限的字节环形缓冲，记录起始偏移与末尾偏移。
- **Policy（策略）**：允许根目录、环境变量过滤规则、命令规则、资源上限。
- **AuditEvent（审计事件）**：时间、Tool、会话、参数摘要、策略判定、结果。
